# Cache Benchmarks (Linear Scale)

- [All Benchmarks Linear Scale](LINEAR.md)
- [All Benchmarks Logarithmic Scale](LOGARITHMIC.md)

Measured by this harness on a 13th Gen Intel(R) Core(TM) i9-13900K with 32 logical CPUs running Ubuntu 26.04 LTS, under the `wsl32coarse` profile. The wsl32 box and the wsl32 working set, sampled coarsely so a number exists before the full matrix finishes. This is a Rust port of [tidwall/cache-benchmarks](https://github.com/tidwall/cache-benchmarks), and these are not the original's numbers, so do not compare a bar here against a bar there. [README.md](README.md) carries the method, the versions and the rest of the hardware.

The Threads on the x axis of every chart below is the number of I/O threads the server was given. It is not the number of clients, which is held at 256 on every point of every chart.

Read [NOTES.md](NOTES.md) first. It is written by hand and it says what is true of these numbers in particular rather than of the harness.

They may not be used to say one engine is faster than another, full stop. This workload has no expiry, no eviction, no mixed command set, no large values, no network, no replication, no persistence and no multi key operations. It is a hot path measurement of two commands. Wherever a number from here is published, that sentence goes with it.

This file is generated by `cache-bench docs` and editing it by hand will not survive the next run.
